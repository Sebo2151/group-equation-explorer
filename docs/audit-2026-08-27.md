# Audit pass and remediation, 2026-08-27

Audit of the Phase 1 prototype described in [audit-handoff.md](audit-handoff.md),
followed by fixes for the confirmed defects. This record separates what was
reproduced from what was only reasoned about, and what was fixed from what was
deliberately left for later phases.

Verification at the end of the pass: `npm test` 53/53,
`npx tsc --noEmit --incremental false` clean, `npm run lint` clean,
`npm run build` succeeds, no browser console errors. Browser checks were run at
1280x720 and at a genuine 390x844 CSS viewport (`innerWidth` reported 390),
which closes the measurement gap the handoff recorded, where a requested 390px
override had actually reported 325px.

## Defects found and fixed

### 1. An unrecognized rule id produced an unsound rewrite

`findCandidates` branched on `rule === 'identity'` and `applyTransformation` on
`rule === 'inverse'` — opposite polarity of the same union. Any other value
passed the candidate check as `inverse` and then rewrote as `identity`:

```
applyTransformation([a, a^-1], 'bogus', 0)  ->  a^-1,  labelled "Identity law"
```

That is `a a^-1 = a^-1`, presented as a group axiom. TypeScript concealed it
because `RuleId` is closed and nothing reaches it at runtime, but the hazard was
never really malformed input: **adding a third rule id would silently inherit
the same behaviour**, matching as `inverse` and rewriting as `identity`.

Fixed by defining matching and rewriting together in one `RULE_TABLE` entry per
rule, so an unknown or half-implemented rule is a lookup failure rather than a
fallthrough. `RULES` is derived from that table, so an advertised rule cannot
exist without an implementation. Regression tests cover both the unknown id and
the table/advertised-rule correspondence.

### 2. Overlapping targets were ambiguous, and factors were the wrong control

In `a a^-1 a` both pairs are legal. The old UI made each factor the click
target, so the shared middle factor carried both `target-start` and
`target-end`, rendered as one self-contained box with two "tap" markers. No
single factor can distinguish two spans that both contain it.

The fix moves the control off the factor and onto the span. Targets are now
`{start, end}`, and each candidate gets its own bracket drawn beneath the
expression covering exactly its factors. Overlapping spans are distributed into
separate rows by `layerTargets`, a greedy interval layering, so there is always
exactly one control per candidate. Hovering or focusing a bracket highlights
only that bracket's span, so the highlight disambiguates too.

The expression and every bracket share one CSS grid, one column per factor, so a
bracket spans its columns without any measurement JavaScript. Verified in the
browser with `START` temporarily set to `a a^-1 a`: two brackets, on separate
rows, each aligned to its own factors within 6px, non-overlapping, applying
genuinely different rewrites (`e a` versus `a e`), each highlighting only its own
span under both real hover and real keyboard focus.

This also generalizes to the Phase 2 requirement for contiguous spans of
arbitrary length, and it removed the need for disabled factor buttons.

### 3. Focus was destroyed after every move

Committing a move unmounted the clicked control and dropped focus to `<body>`,
so a keyboard user re-tabbed from the top of the document for every step.
Focus now moves to the first remaining target, or to the success note, or — when
the selected law no longer applies anywhere — to the new proof line itself.
All three fallbacks were exercised in the browser; the third was found only
because the first implementation still landed on `<body>` in that case.

### 4. The mobile dock covered the active line

At 390x844 the sticky rule dock overlapped the interactive line from the third
step onward, and the completion note sat entirely below the fold, with the page
never scrolling. Fixed with a reserved `--dock-height` band under the proof
sheet, matching `scroll-margin`, and a `scrollIntoView` anchored to whatever
just changed — the success note on the final move, since it renders below the
line and is what has to clear the dock. Measured across all five steps: the dock
never overlaps the current line, the line is always in the viewport, and the
success note is fully visible above the dock at completion.

### 5. Raw TeX leaked into accessible names

`aria-label` values contained TeX source, so a screen reader announced
`a^{-1}` as "a caret left brace minus one right brace". `core.ts` now provides
`factorSpeech` / `expressionSpeech` / `spanSpeech`, rule definitions carry a
`spokenFormula`, and step details are plain words ("a times a inverse is the
identity") rather than TeX. Tests assert that no reason, detail, or spoken form
contains `\`, `^`, `{`, or `}`.

Related rendering change: KaTeX now runs with `output: 'html'`, which emits only
the aria-hidden visual layer. Accessible text comes entirely from the spoken
forms, which also removed the duplicated MathML-plus-annotation reading.

### 6. Expression markup was inaccessible

The wrapper carried `aria-label` on a bare `<span>` with no role, where ARIA
prohibits naming, and every non-target factor was a `disabled <button>` — out of
the tab order and skipped by some assistive-technology navigation. The
expression is now a single `role="math"` element with a spoken label, and
factors are plain spans. The live region was narrowed from the whole proof list
to a dedicated concise one announcing the current expression and target count.

### 7. The reason control was a dead button whose name did not match its label

`<button title={detail}>{reason}</button>` had no `onClick`, and its accessible
name came from `title` ("aa^{-1} is the identity") while its visible text read
"Inverse law" — a WCAG 2.5.3 Label in Name failure, with the detail reachable
only by hover. It is now a real disclosure with `aria-expanded`, showing the
detail inline on click, reachable by touch and keyboard.

### 8. Mobile hid the law and the zero-match explanation

Rule formula, description, and the selection note were all `display: none`
under 820px, so choosing a law with no matches gave only a "0 places" chip. The
formula now stays visible, and the selection note is shown on mobile carrying
the selected law's name, its description, and — for zero matches — an
explanation that the law is still true but has nowhere to apply here.

### 9. `npx tsc --noEmit` failed

`tests/core.test.ts` imported `'../app/core.ts'` with an extension that tsconfig
did not permit (TS5097). Since `node --experimental-strip-types` requires the
extension, the fix was `allowImportingTsExtensions: true` rather than removing
it; app-relative imports now carry `.ts` consistently, which is what lets
`app/proof.ts` be unit-tested directly under Node.

### 10. Smaller corrections

- The lone-identity no-op (`[e] -> []`, both displaying as `e`) is no longer
  offered as a move, so no step can consume a turn without visible effect.
- Completion compares terms via `factorsEqual`, not rendered TeX. This matters
  beyond tidiness: `expressionTex([]) === 'e'`, so a future goal of `e` would
  otherwise be met by both the empty product and an explicit identity.
- Bracket touch targets are 44px tall on mobile, up from 34px-wide factors.
- Factor validation (`validateFactor` / `validateFactors`) rejects conflicting
  flags, non-string bases, and names outside `/^[A-Za-z][0-9]*$/`, and reserves
  `e` for the identity so a rendered `e` always means one thing.

## Security posture

No live vulnerability was found. KaTeX's default `trust: false` was confirmed to
neutralize `\href{javascript:...}` — it renders as inert red text, with
`javascript:` surviving only inside the harmless TeX annotation. No user input
reaches the renderer today.

The latent vector was `factor.base` being interpolated into TeX unescaped, which
becomes an injection point as soon as a parser or import exists; `\rule{9999em}`
also renders and is a layout denial of service. Rather than escaping after the
fact, the accepted base alphabet is now narrow and validated, and the KaTeX
options are pinned explicitly (`trust: false`, `strict: 'ignore'`, `maxSize`,
`maxExpand`) so the policy is reviewable in one place before Phase 2 input work.

## Verified sound, unchanged

Undo, redo, undo across completion, restart, and redo-branch discard were all
correct before this pass and remain so; they simply had no test coverage. The
engine never commutes factors or cancels unequal bases, and rejects negative,
fractional, out-of-range, and `NaN` targets.

## Test coverage added

`tests/core.test.ts` grew from 6 tests to 33, and `tests/proof.test.ts` is new
with 20. Beyond the regression guards for each defect above, the additions cover
both cancellation orders and every intermediate expression, the non-commutation
and unequal-base invariants, non-aliasing of returned factors, target layering,
factor validation, and a replay check that reproduces a finished proof from its
recorded rule/target pairs — the shape the Phase 2 replay acceptance needs.

The proof history was previously untestable because it lived inside the React
component. It now lives in `app/proof.ts` as a pure reducer over
`{lines, index}`, which is what made those 20 tests possible without a DOM.

## Not addressed, deliberately

- **No browser regression suite is committed.** The browser checks in this pass
  were driven ad hoc and are not reusable. This remains the largest verification
  gap; the plan calls for one and it should cover the geometry and focus
  behaviour measured here.
- **No real-device trial.** Emulating a 390px viewport is not a phone. Enlarged
  text, zoom, screen-reader, and landscape passes are still outstanding.
- **`metadataBase` is still unset**, so `/og.png` stays relative. It is a
  hosting question, and the handoff scopes hosting out.
- **Dependency audit advisories remain untriaged**, per the handoff's
  instruction not to change dependencies during review.
- The recursive term model, parser, equation mode, and everything from Phase 2
  onward are unchanged. The `Target` span type and the recorded rule/target on
  each step are the two pieces shaped deliberately to meet them.
